# Настройка на портала

Порталът вече е настроен за portal.buladmin.eu. Тези стъпки са за повторна настройка или за нова среда.

Частите, които не са в Git:

- `worker/.dev.vars`: Google тайна, частен ключ на сертификата, тайни за сесии и пароли.
- `worker/.secrets/buladmin-portal.cer`: публичен сертификат, валиден до 6 ноември 2028 г.

Пазете ги на сигурно място. Без `PASSWORD_PEPPER` съществуващите пароли спират да работят.

## 1. Microsoft и таблици

В tenant-а клиентските тайни са блокирани, затова порталът използва сертификат. Едно и също приложение (`cd4ae5dd-...`) служи за вход и за достъп до таблиците.

```
cd worker
node scripts/setup-microsoft.mjs --operator ваш-имейл@bulmail.eu --name "Вашето Име"
```

Скриптът показва адрес и код. Влезте с акаунт на глобален администратор. След това той:

1. качва сертификата в приложението;
2. добавя `Sites.Selected` с admin consent;
3. дава достъп само до сайта `buladmin`;
4. създава петте таблици: `Портал - Клиенти`, `Заявки`, `История`, `Оператори` и `Акаунти`;
5. добавя първия администратор и отпечатва еднократен линк за паролата му, валиден 72 часа;
6. намалява правата върху сайта от `manage` на `write`.

Скриптът може да се пуска повторно. Изходът съдържа линка за парола, затова не го споделяйте.

### Имейли

Порталът праща от `accounts@portal.buladmin.eu` (потвърждение, нова парола, покани) и от `no-reply@portal.buladmin.eu` (известия по заявките). С акаунт на Exchange администратор:

```
cd worker
powershell -ExecutionPolicy Bypass -File scripts\setup-mail.ps1
```

Скриптът създава двете споделени кутии, ако липсват, и разрешава на приложението да праща само от тях през Exchange RBAC. Накрая `InScope` трябва да е `True` за двете кутии и `False` за Вашата. Промяната може да отнеме от 30 минути до 2 часа.

**Никога не добавяйте `Mail.Send` на приложението в Entra:** там правото важи за всички кутии в tenant-а и ограничението в Exchange спира да има ефект.

След като пращането работи, сложете `MAIL_ENABLED = "true"` в `worker/wrangler.toml` и изпълнете `npm run deploy`. Дотогава регистрацията работи без потвърждение на имейла, а линковете се показват на оператора.

## 2. API в Cloudflare

```
cd worker
npx wrangler@4 login
npm run secrets
npm run deploy
```

Проверка: https://portal.buladmin.eu/api/meta трябва да върне JSON с услугите. Записът на `portal` в Cloudflare DNS трябва да остане **Proxied** (оранжев облак).

**План на Cloudflare:** хеширането на парола отнема десетки милисекунди процесорно време, а безплатният план на Workers дава 10 ms за заявка. Ако входът с парола започне да връща грешка 1102, преминете на платения план Workers Paid.

**Ограничение на опитите за вход:** добавете правило в Cloudflare → Security → WAF → Rate limiting за `/api/auth/*` (например 20 заявки в минута от един IP адрес). То допълва заключването след 5 грешни опита.

## 3. Страници

Качете кода в `main`. GitHub Pages публикува сам, а папките `worker/` и `docs/` не се публикуват.

## Ежедневна работа

- **Вход за оператори:** https://portal.buladmin.eu/operator.html
- **Нов оператор:** администратор → „Оператори“ → „Създайте покана“. Изпратете показания линк на човека лично.
- **Спиране на оператор:** „Деактивирайте“. Отворените му сесии спират веднага.
- **Забравена парола:** „Забравена парола?“ на страницата за вход праща линк, валиден 1 час. Администратор може да изпрати линк от „Оператори“, а оператор на клиент от страницата на клиента.
- **Редакция на клиент:** „Клиенти“ → името на клиента. В историята се записва кой е променил кои полета, без стойностите.
- **ЕГН:** навсякъде е маскирано. Пълното се вижда с „Покажи“ и всеки преглед се записва. В таблицата в SharePoint обаче стои в чист вид.
- **Кой вижда таблиците в SharePoint:** всички с достъп до сайта `buladmin`. Дръжте в него само хора, които може да виждат клиентски данни.
- **Не преименувайте** таблиците и не изтривайте колони, защото порталът ги намира по тези имена.

## Смяна на сертификата

Преди изтичането му генерирайте нов, качете го в приложението и обновете `MS_CERT_PRIVATE_KEY` с `npm run secrets` и `MS_CERT_THUMBPRINT` в `wrangler.toml`.

## Локален преглед без акаунти

```
cd worker
npm run dev
```

Отворете http://localhost:8788/. Клиент може да се регистрира с имейл и парола. Готови демо профили: `/dev/login?as=client`, `as=fresh` или `as=operator`. Покана за оператор: `/set-password.html#t=o.dev-setup`. Данните се губят при спиране. Тестове: `npm test`.
